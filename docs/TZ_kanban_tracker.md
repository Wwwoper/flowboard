# ТЗ: Лёгкий канбан-трекер для пет-проекта

Версия: 1.0 · Дата: 2026-10-22

## 1. Цель

Небольшое self-hosted веб-приложение для личного пет-проекта. Задачи создаются и закрываются за секунды, текущее состояние видно на канбан-доске. После перерыва в работе должно быть сразу понятно, что делать дальше.

## 2. Границы (MVP)

В MVP входит:
- Один пользователь, без авторизации (запуск локально или за reverse proxy).
- Канбан-доска с перетаскиванием.
- Быстрое создание, редактирование, закрытие и удаление задач.
- Вложения к задачам.
- Импорт задач из Markdown.
- Экспорт всех задач одним файлом.

Не входит в MVP: многопользовательский режим, комментарии, уведомления, сроки и напоминания, несколько проектов, мобильное приложение.

## 3. Стек

| Слой | Решение |

## 4. Модель данных

### tasks
| Поле | Тип | Описание |
|---|---|---|
| id | INTEGER PK | Идентификатор |
| title | TEXT NOT NULL | Заголовок, до 200 символов |
| description | TEXT | Описание (Markdown), до 5000 символов |
| status | TEXT NOT NULL | todo / doing / waiting / done |
| position | REAL NOT NULL | Порядок внутри колонки |
| tags | TEXT | Теги через запятую (необязательно) |
| created_at | TEXT | ISO 8601, UTC |
| updated_at | TEXT | ISO 8601, UTC |
| closed_at | TEXT NULL | Заполняется при переходе в done, очищается при выходе из done |

### attachments
| Поле | Тип | Описание |
|---|---|---|
| id | INTEGER PK | Идентификатор |
| task_id | INTEGER FK | Ссылка на задачу, ON DELETE CASCADE |
| filename | TEXT | Исходное имя файла |
| stored_name | TEXT | Имя на диске (uuid + расширение) |
| size | INTEGER | Размер в байтах |
| created_at | TEXT | ISO 8601, UTC |

Файлы хранятся в `data/attachments/<task_id>/<stored_name>`. БД лежит в `data/tracker.db`.

### Статусы
| Код | Колонка |
|---|---|
| todo | К выполнению |
| doing | В работе |
| waiting | Ожидает |
| done | Готово |

## 5. Функциональные требования

### 5.1 Доска
- FR-1. Четыре колонки по статусам, в каждой счётчик задач.
- FR-2. Карточка показывает заголовок, теги, число вложений и дату последнего изменения.
- FR-3. Перетаскивание карточек между колонками и внутри колонки. После drop клиент отправляет PATCH со статусом и позицией.
- FR-4. Колонка «Готово» по умолчанию свёрнута и показывает 5 последних закрытых задач, остальные раскрываются кнопкой.
- FR-5. Колонка «В работе» подсвечивается, если в ней больше 3 задач (мягкий WIP-лимит, значение в конфиге).
- FR-6. Фильтр по тегу и поиск по заголовку на клиенте.

### 5.2 Задачи
- FR-7. Быстрое создание: поле ввода над доской, Enter создаёт задачу в `todo` только с заголовком.
- FR-8. Горячая клавиша `n` переводит фокус на поле быстрого создания.
- FR-9. Клик по карточке открывает панель: редактирование заголовка, описания, статуса, тегов, список вложений.
- FR-10. Кнопка «Закрыть» ставит статус `done` и заполняет `closed_at`.
- FR-11. Удаление задачи с подтверждением; вложения удаляются вместе с ней (записи и файлы).

### 5.3 Вложения
- FR-12. Загрузка одного или нескольких файлов через кнопку и drag-and-drop в панель задачи.
- FR-13. Максимальный размер файла: 20 МБ (настраивается).
- FR-14. Скачивание и удаление вложения.
- FR-15. Имя файла на диске не берётся от пользователя (защита от path traversal); исходное имя хранится только в БД.

### 5.4 Импорт из Markdown
- FR-16. Загрузка одного или нескольких `.md` файлов через UI и эндпоинт `POST /api/import`.
- FR-17. Режим A (frontmatter): один файл равен одной задаче.

```markdown
---
title: Починить авторизацию
status: todo
tags: [backend, bug]
---
Короткое описание задачи.
```

- FR-18. Режим B (чек-лист): строки `- [ ] текст` создают задачи в `todo`, строки `- [x] текст` создают задачи в `done`.
- FR-19. Режим определяется автоматически: есть frontmatter с `title`, значит режим A; иначе режим B.
- FR-20. Если статус неизвестен или не указан, используется `todo`.
- FR-21. Ответ импорта содержит число созданных задач и список пропущенных записей с причинами.
- FR-22. Импорт не удаляет и не изменяет существующие задачи. Дубли по заголовку допускаются (в MVP).

### 5.5 Экспорт
- FR-23. `GET /api/export?format=md` отдаёт один файл `tasks-YYYY-MM-DD.md`: задачи сгруппированы по колонкам, у каждой есть описание, теги, даты и список имён вложений.
- FR-24. `GET /api/export?format=zip` отдаёт ZIP: `tasks.json` и папка `attachments/<task_id>/`. Из него можно полностью восстановить проект.
- FR-25. Формат экспорта в MD совместим с режимом A импорта, чтобы можно было вернуть задачи обратно.

## 6. API

| Метод | Путь | Назначение |
|---|---|---|
| GET | / | Страница с доской |
| GET | /api/tasks | Список задач |
| POST | /api/tasks | Создать задачу (минимум title) |
| GET | /api/tasks/{id} | Получить задачу |
| PATCH | /api/tasks/{id} | Изменить поля, статус, позицию |
| DELETE | /api/tasks/{id} | Удалить задачу |
| POST | /api/tasks/{id}/files | Загрузить вложения |
| GET | /api/files/{attachment_id} | Скачать вложение |
| DELETE | /api/files/{attachment_id} | Удалить вложение |
| POST | /api/import | Импорт .md |
| GET | /api/export | Экспорт (format=md или zip) |

Коды ошибок: 400 (некорректные данные), 404 (не найдено), 413 (файл слишком большой), 422 (валидация FastAPI).

## 7. Нефункциональные требования

- NFR-1. Запуск одной командой: `uv run uvicorn app.main:app`.
- NFR-2. Отклик API на локальной машине меньше 100 мс при 1000 задачах.
- NFR-3. Все данные в каталоге `data/`; бэкап равен копированию каталога.
- NFR-4. Экранирование пользовательского текста при выводе в HTML (защита от XSS); Markdown в описании рендерится с санитизацией.
- NFR-5. Код проходит `ruff check` и `ruff format --check`.
- NFR-6. Работа без внешних CDN: SortableJS кладётся в `static/`.
- NFR-7. Если сервис доступен снаружи, он закрывается reverse proxy с авторизацией (в MVP своей авторизации нет).

## 9. Тесты (минимум)

- CRUD задач: создание, смена статуса, удаление.
- `closed_at` заполняется при переходе в `done` и очищается при выходе из него.
- Импорт: frontmatter, чек-лист, смешанный файл, неизвестный статус, пустой файл.
- Вложения: загрузка, скачивание, превышение лимита, попытка подмены имени (`../`).
- Экспорт MD, затем повторный импорт даёт тот же набор задач.
- Экспорт ZIP содержит `tasks.json` и все вложения.

## 10. Этапы

1. Каркас: uv, FastAPI, схема БД, CRUD задач, тесты.
2. Фронтенд: доска, быстрое создание, drag-and-drop, панель задачи.
3. Вложения.
4. Импорт MD.
5. Экспорт MD и ZIP.
6. Полировка: свёрнутая колонка «Готово», WIP-подсветка, горячие клавиши, Dockerfile, README.

## 11. Критерии приёмки

- Задачу можно создать и закрыть за пару действий, не покидая доски.
- Перетаскивание сохраняет статус и порядок после перезагрузки страницы.
- Файл `.md` с 20 задачами импортируется за один шаг.
- Экспорт одним файлом открывается без специальных программ, а ZIP-экспорт восстанавливает проект целиком.
- Вложения прикрепляются, скачиваются и удаляются вместе с задачей.
