# Регламент ИИ: использование, сохранение и перенос

## Где открыть

Откройте **Настройки → Проекты и организация → Регламент ИИ**. При открытии приложение загружает действующий текст с сервера через `GET /api/ai-task-guidelines`. Если пользовательская редакция не сохранена, сервер возвращает встроенный Markdown-документ, поставляемый вместе с версией приложения.

На странице показаны источник текста, версия встроенного документа и дата последнего сохранения пользовательской редакции (если она есть). Ни браузерный кэш, ни локальное хранилище браузера не являются источником истины для регламента.

## Как пользоваться

1. Прочитайте текст в редакторе. Справа/ниже отображается предпросмотр Markdown.
2. Чтобы изменить регламент, отредактируйте текст и нажмите **«Сохранить изменения»**. Автоматической синхронизации с внешними ИИ-сервисами нет.
3. Чтобы передать регламент выбранной модели, нажмите **«Скопировать регламент»**, затем самостоятельно вставьте текст в выбранный ИИ-сервис. Flowboard не отправляет текст модели автоматически.
4. Чтобы сохранить отдельный файл, нажмите **«Скачать Markdown»**. Будет загружен файл `ai-task-guidelines.md` с текущим содержимым редактора. Если изменения ещё не сохранены, скачанный файл содержит именно текст редактора, а не последнюю серверную редакцию.
5. Чтобы отменить пользовательскую редакцию и вернуться к встроенному документу, нажмите **«Восстановить исходную редакцию»** и подтвердите действие. Сброс удаляет серверное переопределение из SQLite; после этого снова используется документ, поставляемый с приложением.

Изменения в редакторе не сохраняются автоматически. При попытке уйти со страницы, закрыть окно настроек или переключиться на другую вложенную страницу приложение предупреждает о несохранённых изменениях. Подтверждение выхода отменяет текущий черновик; отказ оставляет страницу открытой.

## Где хранится и что гарантируется

- Встроенная редакция хранится как ресурс приложения и доступна независимо от текущего рабочего каталога.
- Пользовательская редакция сохраняется на серверной стороне в существующей SQLite-таблице `app_settings` под ключом `ai_task_guidelines_override`.
- Перезапуск приложения не удаляет сохранённое переопределение: при следующем запросе сервер читает его из SQLite.
- Очистка кэша, cookies или данных сайта в браузере сама по себе не удаляет и не изменяет серверную SQLite-базу. После очистки страницы приложение загружает действующий документ с сервера заново. Если серверная база была отдельно удалена или заменена, это уже другая операция и гарантии сохранения от очистки браузера на неё не распространяются.
- Сохранение не означает резервное копирование. Для переноса пользовательской редакции используйте ZIP-резервную копию Flowboard.

## Перенос на другой каталог или экземпляр

1. На исходном экземпляре сохраните пользовательскую редакцию (если она нужна).
2. Откройте **Настройки → Проекты и организация → Данные и резервные копии** и скачайте ZIP.
3. В ZIP пользовательская редакция включается в `tasks.json` только при наличии сохранённого непустого переопределения. Встроенный документ не копируется: он поставляется с кодом/версией приложения. Другие значения `app_settings` в архив по этому механизму не включаются.
4. Восстановите ZIP в отдельный каталог командой, например:

   ```bash
   uv run python -m app.restore /path/to/backup.zip --data-dir ./data-restored
   TRACKER_DATA_DIR="$PWD/data-restored" uv run uvicorn app.main:app
   ```

5. Откройте страницу «Регламент ИИ» на восстановленном экземпляре и проверьте источник и текст.

Архивы, созданные версиями приложения до поддержки регламента, не содержат поля `ai_task_guidelines_override`. При восстановлении такого архива пользовательское переопределение не создаётся, и используется встроенная редакция текущей версии приложения.

## Проверочный список для ручной проверки в браузере

Эти действия требуют реального браузера и не заменяются серверными unit/API-тестами:

- [ ] Открыть страницу и визуально проверить чтение и предпросмотр встроенного документа.
- [ ] Изменить текст, сохранить, перезапустить приложение и убедиться, что текст остался.
- [ ] Проверить копирование полного текста и содержимое скачанного Markdown-файла.
- [ ] Проверить подтверждение сброса и появление встроенной редакции.
- [ ] Очистить кэш и данные сайта, снова открыть страницу и убедиться, что текст получен с сервера.
- [ ] Изменить текст без сохранения; проверить отмену/подтверждение при возврате, закрытии окна настроек и переходе на другую вложенную страницу.
- [ ] Проверить отображение ошибок при недоступности API и повторную загрузку.

Не следует трактовать очистку данных сайта как удаление данных сервера. Для проверки сохранности серверного состояния отдельно проверьте SQLite или повторно запросите API после перезагрузки страницы.
