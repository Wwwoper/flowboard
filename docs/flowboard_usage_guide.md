# Flowboard: памятка по работе с задачами в нескольких проектах

## 1. Главное правило: один общий канбан, проекты — через теги

В Flowboard все задачи находятся на одной доске. Отдельного поля «Проект» нет, поэтому каждая задача должна иметь **ровно один тег проекта** и **ровно один тег типа**.

### Теги проектов

Используй формат `project:<slug>`: строчные латинские буквы, цифры и дефисы, без пробелов. Выбери название один раз и не меняй его без необходимости.

Примеры:

- `project:storefront` — витрина товаров;
- `project:rope-knots` — Rope Knots;
- `project:template-menu` — меню по дням;
- `project:kanban-tracker` — сам Flowboard.

Для нового проекта создай новый тег, например `project:my-new-app`. Не заводи несколько тегов для одного проекта (`project:storefront` и `storefront`) — задачи расползутся между фильтрами.

### Теги типа задачи

Выбирай один основной тип:

- `bug` — существующее поведение работает неправильно;
- `feature` — новая возможность или заметное изменение поведения;
- `docs` — документация, инструкции или поясняющие тексты;
- `refactor` — изменение внутренней структуры без изменения поведения для пользователя.

При необходимости можно добавить 1–2 уточняющих тега, например `backend`, `frontend`, `tests` или `ux`. Не превращай каждый термин в тег.

**Пример поля тегов:** `project:storefront, feature, frontend`.
В интерфейсе теги вводятся через запятую.

## 2. Как разделить работу по проектам

1. Открой фильтр тегов и выбери `project:<slug>` нужного проекта.
2. При необходимости введи ключевое слово в поиск, чтобы сузить список задач.
3. Закончив работу с проектом, переключи тег на другой проект.

Фильтр поддерживает **один тег за раз**. Поиск работает по заголовкам задач, а не по описаниям. Поэтому делай заголовки конкретными и обязательно ставь тег проекта.

## 3. Жизненный цикл задачи

- **К выполнению (`todo`)** — задача сформулирована, но ещё не взята в работу.
- **В работе (`doing`)** — над задачей действительно работаешь сейчас. Старайся держать здесь не больше 1–3 задач; после трёх приложение показывает предупреждение.
- **Ожидает (`waiting`)** — продолжение заблокировано внешним ответом, решением или другой зависимостью. Кратко укажи причину в описании.
- **Готово (`done`)** — результат проверен и соответствует условиям задачи.

Не используй `waiting` как дополнительный список «когда-нибудь». Незакрытые идеи оставляй в `todo`. Колонка «Готово» свёрнута и показывает пять последних задач; нажми «Показать все», чтобы увидеть остальные.

## 4. Создание и ведение карточки

1. Введи короткий заголовок в поле над доской и нажми Enter.
2. Открой созданную карточку, добавь тег проекта и тег типа.
3. Заполни короткое описание: что не работает или что нужно получить, а при необходимости — как проверить результат.
4. Перетаскивай карточку между колонками или меняй её порядок перетаскиванием.
5. После проверки результата переведи задачу в «Готово».

Одна карточка — один понятный результат. Если в задаче несколько независимых результатов, раздели её на несколько карточек. В текущем MVP нет подзадач и отдельных досок по проектам.

### Короткий формат описания

Для ошибки:

```text
Проблема: что происходит сейчас.
Ожидалось: какое поведение должно быть.
Проверка: как быстро убедиться, что исправлено. (если нужно)
```

Для доработки:

```text
Нужно: какое изменение требуется.
Готово, когда: 1–3 проверяемых условия.
```

Обычно достаточно 2–5 строк. Не переписывай в описание всю историю обсуждения и не добавляй общие фразы вроде «сделать качественно».

## 5. Полезные действия

- `N` — перейти к быстрому созданию задачи;
- `⌘/Ctrl + K` — перейти к поиску;
- `Esc` — закрыть панель задачи.

Карточка открывается нажатием на неё. В панели можно редактировать заголовок, описание, статус и теги, а также добавлять вложения.

## 6. Импорт, экспорт и резервные копии

- **Импорт MD** — загрузка одного или нескольких Markdown-файлов. Для обычного формата frontmatter один файл создаёт одну задачу.
- **Экспорт MD** — удобный текстовый список задач; имена вложений перечисляются, но сами файлы в Markdown не упаковываются.
- **Резервная копия ZIP** — основной вариант бэкапа: содержит `tasks.json` и файлы вложений.

Делай ZIP-резервную копию после важных изменений или перед крупной переработкой. Повторный импорт **не проверяет дубликаты** и не обновляет существующие карточки — он добавляет новые. Не импортируй один и тот же файл повторно, если не хочешь получить копии задач.

## 7. Еженедельная уборка доски

- Проверь, что у каждой активной задачи есть один `project:*` и один тег типа.
- Верни в `todo` задачи, которыми больше не занимаешься; укажи причину у задач в `waiting`.
- Закрой проверенные задачи и удали случайные дубли вручную.
- Сохрани ZIP-резервную копию.

**Краткое правило:** тег проекта отвечает на вопрос «к какому проекту относится задача?», тег типа — «что это за работа?», статус — «на каком этапе она находится?». Не смешивай эти три назначения.
