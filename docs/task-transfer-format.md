# Формат переноса отдельной задачи

Из панели задачи нажмите **«Экспорт ZIP»**, чтобы скачать архив одной карточки. Этот архив предназначен для переноса одной задачи между экземплярами Flowboard: он не является полной резервной копией и не содержит остальные задачи, рабочие наборы или историю доски.

## Структура

```text
task-<id>.zip
├── task.json
└── attachments/
    ├── 0001.png
    └── 0002.txt
```

`task.json` — UTF-8 JSON следующей версии:

```json
{
  "format": "flowboard-task",
  "format_version": 1,
  "task": {
    "title": "Task title",
    "description": "Task description",
    "result": "",
    "status": "todo",
    "tags": ["project:flowboard"],
    "task_type": "feature",
    "created_at": "2026-11-05T10:10:59Z",
    "updated_at": "2026-11-05T10:27:41Z",
    "closed_at": null
  },
  "attachments": [
    {
      "path": "attachments/0001.png",
      "filename": "screenshot.png",
      "size": 12345,
      "created_at": "2026-11-05T10:15:00Z"
    }
  ]
}
```

## Импорт

Кнопка «Импорт задач» в текущем интерфейсе принимает Markdown-файлы (`.md`). ZIP отдельной задачи импортируется через API `POST /api/import`, например при запущенном локальном приложении:

```bash
curl -X POST http://127.0.0.1:8000/api/import \
  -F "files=@task-123.zip"
```

Успешный импорт создаёт новую задачу с новыми ID задачи и вложений. Существующие задачи не обновляются; повторный импорт создаст ещё одну карточку. В ответе API указано количество созданных задач и список пропущенных файлов с причинами.

## Правила

- `format` и `format_version` обязательны; неизвестный формат или версия отклоняются.
- `task` — объект с полями задачи. `title`, `description`, `result`, `status`, `tags` и `task_type` проверяются по типам и ограничениям приложения.
- Допустимые статусы: `todo`, `doing`, `waiting`, `done`. Допустимые типы: `bug`, `feature`, `docs`, `refactor` или пустая строка.
- `tags` — массив строк; в базе теги сохраняются в существующем формате через запятую.
- Даты передаются в ISO 8601; отсутствующая дата закрытия передаётся как `null`.
- `attachments` — массив объектов. `path` указывает на файл внутри ZIP, `filename` сохраняет исходное имя, `size` — точный размер в байтах.
- ID задачи и вложений не переносятся. При импорте создаются новые записи с новыми ID.
- ZIP не извлекается по произвольным путям. Повторяющиеся имена, небезопасные пути, лишние файлы, повреждённые данные и несовпадение размеров отклоняются.
- Лимиты импорта: ZIP до 50 МБ, не более 101 записи вместе с `task.json`, распакованный объём до 100 МБ, `task.json` до 1 МБ; размер каждого вложения ограничен настройкой `TRACKER_MAX_FILE_SIZE_MB` (по умолчанию 20 МБ).
- Импорт одной задачи создаёт новую задачу и не обновляет существующие записи. ID задачи и вложений генерируются заново; исходные ID не входят в формат переноса.
- Импорт Markdown остаётся отдельным сценарием массового добавления задач. ZIP отдельной задачи не следует путать с полной ZIP-резервной копией `GET /api/export?format=zip`: последняя содержит все задачи, вложения и данные рабочих наборов и восстанавливается отдельной командой `app.restore`, а не через `POST /api/import`.
