# Рабочие наборы

Рабочие наборы — необязательные временные группы задач одного проекта. Проект по-прежнему определяется тегом `project:<slug>`; отдельная сущность проекта не вводится.

## Поведение

- У рабочего набора есть название, проект и состояние `active` или `completed`.
- Пустой набор после создания остаётся активным, чтобы пользователь мог добавить задачи позже.
- Одна задача может иметь не более одной текущей связи с рабочим набором.
- Новую задачу можно создать в выбранном наборе; существующую — добавить, удалить или перенести между наборами. Перенос выполняется одной операцией после подтверждения пользователя.
- Добавлять задачи можно только в активный набор и только если тег проекта задачи совпадает с проектом набора.
- Если все текущие задачи набора имеют статус `done` и их количество больше нуля, набор автоматически становится завершённым.
- Повторное открытие задачи автоматически активирует набор. Статусы других задач не меняются. При повторном закрытии последней открытой задачи набор завершается снова.
- При явном удалении последней задачи из набора сам набор удаляется. События удаления сохраняются в истории проекта.
- Удаление задачи из проекта записывается в историю; если это была последняя задача набора, набор удаляется.
- Завершённый набор можно переименовать, но его состав нельзя менять удалением членства или переносом задачи. Удаление самой задачи из проекта остаётся отдельным действием и фиксируется как `task_deleted`. Ручной активации нет.

## Хранение

- `worksets` хранит наборы и состояние жизненного цикла.
- `workset_memberships` хранит только текущие связи; уникальность `task_id` обеспечивает ограничение «не более одного набора» на уровне SQLite.
- `workset_events` — append-only журнал с неизменяемыми историческими `workset_id`/`task_id`, снимками названия, статуса задачи и датой её закрытия. Исторические ID не являются внешними ключами и сохраняются после физического удаления задачи или набора.
- Состав и периоды членства восстанавливаются из событий `task_added`, `task_removed` и `task_deleted`; повторное добавление создаёт новый период.
- Подробные правила, схема событий и критерии проверки описаны в [`workset-history.md`](workset-history.md).
- Выбранный набор хранится в `localStorage` отдельно для каждого проекта.
- ZIP-резервная копия включает наборы, текущие связи и события. Восстановление старого ZIP без этих полей остаётся поддерживаемым.

## Интерфейс

- Переключатель на панели доски показывает все задачи или выбранный набор.
- Активные наборы доступны в основном переключателе; завершённые и удалённые — через историю. История показывает состав на момент последнего завершения (или текущий состав для активного набора), ранее убранные задачи и хронологию событий.
- Название набора можно изменить кнопкой «Переименовать».
- В панели задачи поле «Рабочий набор» позволяет добавлять задачу в активный набор, снимать связь или переносить задачу между наборами. Для задачи в завершённом наборе поле заблокировано.
